KaraAPI

KaraAPI is a modern Paper plugin API/framework designed to make plugin development cleaner, faster, and more structured.

It provides a central runtime that bootstraps host plugins, manages lifecycle services, tasks, commands, menus, UI, configuration, messages, placeholders, storage, registries, profiles, custom items, requirements, and regions.

KaraAPI is designed around this rule:

KaraAPI manages the runtime.
The host plugin owns its commands, listeners, tasks, configs, messages, items, and services.

Features

  • Central bootstrapping through KaraAPI.boot(...)
  • Per-plugin runtime kernel
  • Lifecycle-aware service container
  • Startable, Stoppable, and Tickable interfaces
  • Tick orchestrator grouped by tick interval
  • Task API with task groups
  • Config API for YAML files
  • Message API with MiniMessage support
  • Local placeholders and optional PlaceholderAPI support
  • PlaceholderAPI expansion registration
  • Registry API for ID-based systems
  • Storage/repository API
  • Profile cache API
  • Command tree API
  • Menu/inventory GUI API
  • Item builders and custom item API
  • UI helpers for chat, action bar, title, boss bar, and sidebar
  • Color and gradient utilities
  • Requirement API
  • Region API
  • Internal Paper adapter layer

Compatibility

KaraAPI is primarily designed for:

Paper 1.21+
Java 21
Non-Folia servers

Some systems may work on older Paper versions, but the API uses modern Paper/Adventure concepts such as Component-based UI, item meta components, and modern scheduling wrappers.

Folia is not officially supported by the current task scheduler implementation. A Folia scheduler adapter can be added later behind the paper.scheduler package.

Package meanings

api      = public API used by host plugins
runtime  = KaraAPI boot/shutdown engine
paper    = raw Bukkit/Paper adapter layer
internal = private KaraAPI implementation helpers
root     = KaraAPI's own plugin main class

Host plugins should mainly import from:

org.kerix.karaapi.api.*

They should not depend directly on:

org.kerix.karaapi.runtime.*
org.kerix.karaapi.paper.*
org.kerix.karaapi.internal.*

Installing KaraAPI as a Dependency

KaraAPI plugin.yml

name: KaraAPI
version: '${version}'
main: org.kerix.karaapi.KaraAPIPlugin
api-version: '1.21'
authors:
  - Kerix
description: Core API library for Kara plugins.
load: STARTUP
softdepend:
  - PlaceholderAPI

Host plugin plugin.yml

A plugin that uses KaraAPI should depend on it:

name: ExamplePlugin
version: '1.0.0'
main: com.example.exampleplugin.ExamplePlugin
api-version: '1.21'
authors:
  - Kerix

depend:
  - KaraAPI

commands:
  example:
    description: Example command
    usage: /example

If your host plugin also directly uses PlaceholderAPI behavior, you may add:

softdepend:
  - PlaceholderAPI

Gradle Setup

Step 1. Add the JitPack repository in your settings.gradle.kts at the end of repositories:

dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)

    repositories {
        mavenCentral()
        maven { url = uri("https://jitpack.io") }
    }
}

Step 2. Add KaraAPI as a dependency in your build.gradle.kts:

dependencies {
    implementation("com.github.Karalium:KaraAPI:Tag")
}

Replace Tag with the release tag you want to use, for example:

implementation("com.github.Karalium:KaraAPI:v1.0.0")

If KaraAPI is installed as a separate plugin on the server, you can use compileOnly instead of implementation:

dependencies {
    compileOnly("com.github.Karalium:KaraAPI:Tag")
}

KaraAPI itself should be installed as a plugin on the server when another plugin depends on it.

Bootstrapping a Host Plugin

A host plugin should be very small. It delegates bootstrapping to KaraAPI.

package com.example.exampleplugin;

import org.bukkit.plugin.java.JavaPlugin;
import org.kerix.karaapi.api.KaraAPI;
import org.kerix.karaapi.api.PluginHandle;

public final class ExamplePlugin extends JavaPlugin {

    private PluginHandle handle;

    @Override
    public void onEnable() {
        this.handle = KaraAPI.boot(
                this,
                new CoreModule(),
                new CommandModule(),
                new ListenerModule(),
                new PlaceholderModule()
        );
    }

    @Override
    public void onDisable() {
        if (handle != null) {
            handle.shutdown();
        }
    }
}

Plugin Modules

Modules are where you register services, commands, listeners, messages, items, profiles, and other plugin systems.

package com.example.exampleplugin;

import org.kerix.karaapi.api.bootstrap.BootstrapContext;
import org.kerix.karaapi.api.bootstrap.PluginModule;

public final class CoreModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.hostPlugin().getLogger().info("Configuring core systems...");
    }
}

Each module receives a BootstrapContext.

BootstrapContext

BootstrapContext exposes all core services for the host plugin:

context.hostPlugin();
context.apiPlugin();

context.services();
context.ticks();
context.tasks();
context.configs();
context.commands();
context.listeners();
context.announcer();

context.ui();
context.menus();
context.messages();
context.placeholders();

context.registries();
context.storage();
context.profiles();
context.customItems();
context.requirements();
context.regions();

You can also retrieve services through the service container:

MyService service = context.service(MyService.class);

ServiceContainer

ServiceContainer is KaraAPI’s dependency/lifecycle container.

It replaces the older name ServiceRegistry to avoid confusion with RegistryService.

context.services().bind(MyService.class, new MyService());
MyService service = context.services().get(MyService.class);

Services may implement lifecycle interfaces:

import org.kerix.karaapi.api.lifecycle.Startable;
import org.kerix.karaapi.api.lifecycle.Stoppable;
import org.kerix.karaapi.api.lifecycle.Tickable;

public final class MyService implements Startable, Stoppable, Tickable {

    @Override
    public void start() {
        System.out.println("Started");
    }

    @Override
    public void stop() {
        System.out.println("Stopped");
    }

    @Override
    public long tickInterval() {
        return 20L;
    }

    @Override
    public void tick() {
        System.out.println("Tick every second");
    }
}

When bound to the container:

context.services().bind(MyService.class, new MyService());

KaraAPI will:

  1. Start it if it implements Startable
  2. Register it with the tick orchestrator if it implements Tickable
  3. Stop it on shutdown if it implements Stoppable

Task API

Use TaskService instead of directly calling Bukkit’s scheduler.

context.tasks().sync(() -> {
    player.sendMessage("Runs on the main thread");
});

Run later:

context.tasks().later(20L, () -> {
    player.sendMessage("Ran one second later");
});

Repeating task:

context.tasks().timer(0L, 20L, () -> {
    player.sendMessage("Runs every second");
});

Controlled repeating task:

final int[] countdown = {5};

context.tasks().defaultGroup().timerControlled(0L, 20L, handle -> {
    if (countdown[0] <= 0) {
        handle.cancel();
        return;
    }

    player.sendMessage("Countdown: " + countdown[0]);
    countdown[0]--;
});

Task groups:

context.tasks().group("lobby").timer("scoreboard", 0L, 20L, () -> {
    // update scoreboard
});

context.tasks().cancelGroup("lobby");

Tick API

For lifecycle services that need ticking, implement Tickable:

public final class LobbyTicker implements Tickable {

    @Override
    public long tickInterval() {
        return 20L;
    }

    @Override
    public void tick() {
        // runs every 20 ticks
    }
}

Bind it:

context.services().bind(LobbyTicker.class, new LobbyTicker());

KaraAPI groups tickables by interval so all tickables with the same interval share one Bukkit task.

Config API

Load config.yml:

YamlConfig config = context.configs().main();

Load another file:

YamlConfig messages = context.configs().config("messages.yml");
YamlConfig arenas = context.configs().config("arenas/spawn.yml");

Typed keys:

public final class MyConfigKeys {

    public static final ConfigKey<String> SERVER_NAME =
            ConfigKey.string("server.name", "Kara Server");

    public static final ConfigKey<Integer> MAX_PLAYERS =
            ConfigKey.integer("server.max-players", 100);

    private MyConfigKeys() {
    }
}

Usage:

String serverName = config.get(MyConfigKeys.SERVER_NAME);
int maxPlayers = config.get(MyConfigKeys.MAX_PLAYERS);

config.set(MyConfigKeys.SERVER_NAME, "New Server Name");
config.save();

Message API

Messages are loaded from messages.yml.

Example messages.yml:

prefix: "<gray>[<aqua>Kara</aqua>]</gray>"

messages:
  welcome: "<prefix> <green>Welcome, <player>!</green>"
  coins: "<prefix> <yellow>You have <coins> coins.</yellow>"
  gradient: "<gradient:#00ffaa:#ff00ff>Hello <player></gradient>"
  papi: "<prefix> <gray>Server online: %server_online%</gray>"

Define keys:

public final class MyMessages {

    public static final MessageKey WELCOME = MessageKey.of(
            "messages.welcome",
            "<prefix> <green>Welcome, <player>!</green>"
    );

    public static final MessageKey COINS = MessageKey.of(
            "messages.coins",
            "<prefix> <yellow>You have <coins> coins.</yellow>"
    );

    private MyMessages() {
    }
}

Send a message:

context.messages().send(
        player,
        MyMessages.WELCOME,
        PlaceholderSet.empty().add("player", player.getName())
);

Render a component:

Component component = context.messages().component(
        player,
        "<gradient:#00ffaa:#ff00ff>Hello <player>, online: %server_online%</gradient>",
        PlaceholderSet.empty().add("player", player.getName())
);

Rendering order

raw text
→ local placeholders
→ PlaceholderAPI placeholders, if PlaceholderAPI is installed
→ MiniMessage tags and gradients
→ Adventure Component

So this works:

context.ui().chat(
        player,
        "<gradient:#00ffaa:#ff00ff>Hello <player>, online: %server_online%</gradient>",
        PlaceholderSet.empty().add("player", player.getName())
);

Placeholder API

KaraAPI has its own placeholder system that works even if PlaceholderAPI is not installed.

PlaceholderSet placeholders = PlaceholderSet.empty()
        .add("player", player.getName())
        .add("coins", 250);

This replaces:

<player>
<coins>
%player%
%coins%

Example:

Component component = context.messages().component(
        player,
        "<green>Hello <player>, coins: <coins></green>",
        placeholders
);

PlaceholderAPI support

If PlaceholderAPI is installed, KaraAPI also resolves placeholders like:

%player_name%
%server_online%
%vault_eco_balance%

If PlaceholderAPI is absent, local placeholders still work. PlaceholderAPI placeholders remain unresolved as text.

Creating PlaceholderAPI Expansions

Host plugins can register PlaceholderAPI expansions through KaraAPI.

public final class PlaceholderModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.placeholders().registerExpansion(
                KaraPlaceholderExpansion.of(
                        context.hostPlugin(),
                        "example",
                        (player, params) -> {
                            if (player == null) {
                                return "";
                            }

                            return switch (params.toLowerCase()) {
                                case "name" -> player.getName();
                                case "online" -> String.valueOf(player.isOnline());
                                case "coins" -> "250";
                                case "rank" -> "Admin";
                                default -> null;
                            };
                        }
                )
        );
    }
}

This creates PlaceholderAPI placeholders:

%example_name%
%example_online%
%example_coins%
%example_rank%

If PlaceholderAPI is not installed, registration safely returns false and KaraAPI keeps working.

UI API

The UI API supports chat, action bar, titles, boss bars, and sidebars.

Chat

context.ui().chat(
        player,
        "<green>Hello <player></green>",
        PlaceholderSet.empty().add("player", player.getName())
);

Action bar

context.ui().actionBar(
        player,
        "<gradient:#00ffaa:#ff00ff>Dash Ready!</gradient>",
        PlaceholderSet.empty()
);

Gradient action bar using KaraAPI gradient object

context.ui().gradientActionBar(
        player,
        "Coins: <coins>",
        PlaceholderSet.empty().add("coins", 250),
        "#ffaa00",
        "#ffff00"
);

Title

context.ui().title(
        player,
        "<gradient:#00ffaa:#00ffff>Welcome</gradient>",
        "<gray>Hello <player></gray>",
        PlaceholderSet.empty().add("player", player.getName())
);

Boss bar

BossBarHandle bar = context.ui().bossBar(
        player,
        "<red>Boss Fight</red>",
        PlaceholderSet.empty(),
        1.0F,
        BossBar.Color.RED,

bar.show(player);

Sidebar

context.ui().sidebar(
        player,
        "<gradient:#00ffaa:#ff00ff>Kara Server</gradient>",
        PlaceholderSet.empty()
).lines(
        context.messages().component(player, "<yellow>Coins: <coins></yellow>", PlaceholderSet.empty().add("coins", 250)),
        context.messages().component(player, "<gray>Online: %server_online%</gray>", PlaceholderSet.empty())
);

Create gradient components directly:

Component component = ColorGradient.of("#00ffaa", "#ff00ff")

Component component = KaraUI.gradient(
        "Gradient Text",
        "#00ffaa",

context.messages().component(

Command API

Commands are built using command nodes.

plugin.yml:

commands:
  example:
    description: Example command
    usage: /example

Register command:

public final class CommandModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.commands().register(
                KaraCommands.command("example")
                        .usage("/example <reload|coins>")
                        .permission("example.use")

                        .then(KaraCommands.command("reload")
                                .permission("example.reload")
                                .executes(ctx -> {
                                    context.configs().reloadAll();
                                    context.messages().reloadAll();
                                    return CommandResult.message("Reloaded.");
                                }))

                        .then(KaraCommands.command("coins")
                                .playerOnly()
                                .executes(ctx -> {
                                    ctx.player().sendMessage("You have 250 coins.");
                                    return CommandResult.success();
                                }))

                        .build()
        );
    }
}

Arguments:

String target = ctx.arguments().get(0);
int amount = ctx.arguments().integer(1);
String reason = ctx.arguments().join(2);

Suggestions:

.suggests((ctx, current) -> context.hostPlugin()
        .getServer()
        .getOnlinePlayers()
        .stream()
        .map(Player::getName)
        .toList())

Menu API

Create inventory GUIs without manually handling inventory events.

Menu menu = Menu.builder(
        KaraUI.gradient("Shop", "#00ffaa", "#00ffff"),
        3
).border(
        ItemBuilder.of(Material.GRAY_STAINED_GLASS_PANE)
                .name(Component.empty())
                .build()
).slot(
        11,
        ItemBuilder.of(Material.DIAMOND_SWORD)
                .name(KaraUI.gradient("Sword", "#00ffff", "#ff00ff"))
                .lore(Component.text("Click to buy"))
                .build(),
        click -> {
            click.player().sendMessage("Bought sword.");
            click.closeNextTick();
        }
).slot(
        15,
        ItemBuilder.of(Material.BARRIER)
                .name(Component.text("Close"))
                .build(),
        MenuClick::closeNextTick
).build();

context.menus().open(player, menu);

Paginated menus

List<MenuItem> items = rewards.stream()
        .map(reward -> MenuItem.of(
                reward.icon(),

                    click.player().sendMessage("Selected " + reward.name());

PaginationControls controls = new PaginationControls(

PaginatedMenu paginated = PaginatedMenu.of(

Custom Item API

Create a custom item:

public final class MagicSwordItem implements CustomItem {

    @Override
    public String id() {
        return "magic_sword";
    }

    @Override
    public ItemStack create() {
        return ItemBuilder.of(Material.DIAMOND_SWORD)
                .name(KaraUI.gradient("Magic Sword", "#00ffaa", "#ff00ff"))
                .lore(Component.text("A custom KaraAPI item."))
                .build();
    }

    @Override
    public void onAttack(CustomItemAttack event) {
        event.damage(event.event().getDamage() + 4.0);
        event.player().sendMessage(Component.text("Magic hit!"));
    }
}

Register it:

context.customItems().register(new MagicSwordItem());

Give it to a player:

player.getInventory().addItem(
        context.customItems().create("magic_sword")
);

Check an item:

boolean isMagicSword = context.customItems().is(item, "magic_sword");

Custom items are tagged using ItemMeta#getPersistentDataContainer().

Registry API

Use RegistryService for ID-based object registries.

MutableRegistry<Menu> menus = context.registries().getOrCreate("menus");

menus.register("shop", shopMenu);

Menu shop = menus.get("shop");
context.menus().open(player, shop);

Create any custom registry:

MutableRegistry<Ability> abilities = context.registries().getOrCreate("abilities");
abilities.register("dash", new DashAbility());

Do not confuse this with ServiceContainer.

ServiceContainer = dependency/lifecycle services
RegistryService  = ID-based registries for plugin content

Storage API

Create a repository using YAML files.

Example data class:

public record PlayerData(
        UUID id,
        int coins
) {
}

Codec:

StorageCodec<PlayerData> codec = new StorageCodec<>() {

    @Override
    public void write(ConfigurationSection section, PlayerData value) {
        section.set("uuid", value.id().toString());
        section.set("coins", value.coins());
    }

    @Override
    public PlayerData read(ConfigurationSection section) {
        return new PlayerData(
                UUID.fromString(section.getString("uuid")),
                section.getInt("coins")
        );
    }
};

Repository:

Repository<UUID, PlayerData> repository = context.storage().yamlRepository(
        "profiles",
        "profiles",
        UUID::toString,
        UUID::fromString,
        codec
);

Save/load:

repository.save(player.getUniqueId(), new PlayerData(player.getUniqueId(), 100));

PlayerData data = repository.load(player.getUniqueId())
        .orElse(new PlayerData(player.getUniqueId(), 0));

Files are stored under:

plugins/YourPlugin/profiles/<uuid>.yml

Profile API

Profiles are cached objects backed by a repository.

ProfileCache<PlayerData> profiles = context.profiles().create(
        "players",
        repository,
        uuid -> new PlayerData(uuid, 0)
);

Load:

PlayerData data = profiles.getOrLoad(player.getUniqueId());

Save:

profiles.save(player.getUniqueId());

Save and unload:

profiles.saveAndUnload(player.getUniqueId());

Save all on shutdown:

profiles.saveAll();

ProfileService automatically saves and unloads profile caches when KaraAPI shuts down.

Requirement API

Requirements are reusable checks for commands, menus, items, regions, abilities, and actions.

Requirement<Player> canUse = Requirements.all(
        Requirements.world("world"),
        Requirements.predicate(
                player -> player.getLevel() >= 10,
                "You need level 10."
        )
);

RequirementResult result = canUse.check(player);

if (result.denied()) {
    player.sendMessage(result.message());
    return;
}

Register reusable requirements:

context.requirements().register(
        "level_10",
        Requirements.predicate(
                player -> player.getLevel() >= 10,
                "You need level 10."
        )
);

Retrieve:

Requirement<Player> level10 = context.requirements().get("level_10");

Region API

Register a cuboid region:

Region spawn = new CuboidRegion(
        "spawn",
        firstLocation,
        secondLocation
);

context.regions().register(spawn);

Check if a player is inside:

if (context.regions().contains("spawn", player.getLocation())) {
    player.sendMessage("You are in spawn.");
}

Get regions at a location:

List<Region> regions = context.regions().at(player.getLocation());

Get players inside:

List<Player> players = context.regions().playersInside("spawn");

Random location:

Location random = context.regions().randomLocation("spawn");
player.teleport(random);

Sphere region:

Region arena = new SphereRegion(
        "arena",
        centerLocation,
        25.0
);

context.regions().register(arena);

Listener Registration

Register Bukkit listeners through KaraAPI:

public final class ListenerModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.listeners().register(new JoinListener());
    }
}
public final class JoinListener implements Listener {

    @EventHandler
    public void onJoin(PlayerJoinEvent event) {
        event.getPlayer().sendMessage("Welcome.");
    }
}

Startup Messages

StartupAnnouncer uses the host plugin’s name, version, and authors, not KaraAPI’s.

So if ExamplePlugin uses KaraAPI, startup logs say:

ExamplePlugin is starting...
Version: 1.0.0
Authors: Kerix
Powered by KaraAPI

This is intentional:

KaraAPI provides the runtime.
The host plugin owns the startup identity.

Best Practices

Use ServiceContainer for services

context.services().bind(MyService.class, new MyService());

Use RegistryService for content registries

context.registries().getOrCreate("abilities");

Use MessageService for rendered components

context.messages().component(player, raw, placeholders);

Use UiService for output

context.ui().chat(player, raw, placeholders);
context.ui().actionBar(player, raw, placeholders);
context.ui().title(player, title, subtitle, placeholders);

Use local placeholders for your own messages

PlaceholderSet.empty().add("coins", 250);

Use PlaceholderAPI only for external placeholders

%player_name%
%server_online%
%vault_eco_balance%

Use closeNextTick() and openNextTick(...) in menus

This avoids unsafe inventory changes during click events.

click.closeNextTick();
click.openNextTick(otherMenu);

Quick Full Example

public final class ExamplePlugin extends JavaPlugin {

    private PluginHandle handle;

    @Override
    public void onEnable() {
        this.handle = KaraAPI.boot(
                this,
                new CoreModule(),
                new CommandModule()
        );
    }

    @Override
    public void onDisable() {
        if (handle != null) {
            handle.shutdown();
        }
    }
}
public final class CoreModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.customItems().register(new MagicSwordItem());

        context.regions().register(
                new SphereRegion(
                        "spawn",
                        context.hostPlugin().getServer().getWorld("world").getSpawnLocation(),
                        20.0
                )
        );
    }
}
public final class CommandModule implements PluginModule {

    @Override
    public void configure(BootstrapContext context) {
        context.commands().register(
                KaraCommands.command("example")
                        .playerOnly()
                        .then(KaraCommands.command("sword")
                                .executes(ctx -> {
                                    ctx.player().getInventory().addItem(
                                            context.customItems().create("magic_sword")
                                    );

                                    context.ui().chat(
                                            ctx.player(),
                                            "<gradient:#00ffaa:#ff00ff>Given magic sword to <player></gradient>",
                                            PlaceholderSet.empty().add("player", ctx.player().getName())
                                    );

                                    return CommandResult.success();
                                }))
                        .build()
        );
    }
}
